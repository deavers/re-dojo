# Lab 18 — Lazy Singleton (Tier E+ · 2.0)

**Предпосылки:** Lab 04 (цепочки указателей).
**Новая идея:** многие движки держат свои менеджеры за статическим указателем, который остаётся `NULL`, пока
объект не понадобится впервые. Скан указателей, сделанный слишком рано, ничего не находит: база становится
полезной только после ленивой инициализации.

## Цель

Открыть сокровищницу, имея не меньше 99999 самоцветов. Каждый поход в подземелье даёт один самоцвет.

## Сборка и запуск

```powershell
cmake --build build --config Release --target lab18_lazy_singleton
.\build\bin\Release\lab18_lazy_singleton.exe
```

## Как проверяется

* Флаг печатает программа; в репо — только его sha256 (`check/expected.json`).
* Автопроверка (CTest): `lab18_build`, `lab18_solve_ok`, `lab18_wrong_fails`. Selftest сначала выполняет
  ленивую инициализацию (`act enter`), потом проходит цепочку от статического указателя. Читать и писать
  можно только в три объекта графа, поэтому неверная цепочка проваливается, а не роняет харнесс. Неверные
  ответы: цепочка до инициализации (указатель `NULL`), пропущен уровень, неверное первое смещение, последнее
  смещение мимо поля, мало самоцветов, запись не по цепочке.
* Цепочка проверяется от `g_pGameManager`. Сам адрес статического указателя (module+offset) зависит от сборки
  и проверяется вручную в Cheat Engine.
* `solve/solve.py` — спойлер.

## Где пригодится на карте

Менеджеры, синглтоны и «мир» в движках: указатель есть всегда, но объект появляется только после загрузки
уровня или первого обращения.
