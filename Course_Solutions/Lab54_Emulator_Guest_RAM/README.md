# Lab 54 — Own Emulator: Guest RAM (Tier A · 6.5)

**Предпосылки:** Lab 18 (статический объект → указатель → данные); Lab 24 (битовые поля) — в плане, ещё не собрана.
**Новая идея:** в эмулируемой консоли переменные игры лежат в гостевой RAM — это просто буфер в куче эмулятора
(хоста). Мануал консоли даёт гостевые адреса, Cheat Engine видит адреса хоста. Найди базу гостевой RAM на
хосте (адрес на хосте − гостевой адрес), найди указатель эмулятора на неё и переводи гостевые адреса в адреса
хоста.

## Цель

Внутри консоли: жизней ровно 99, счёт не меньше 50000. По мануалу: жизни — гостевой `0x0300` (u8), счёт —
гостевой `0x0302` (u16, little-endian). Буфер гостевой RAM при каждом запуске оказывается в другом месте кучи.

## Сборка и запуск

```powershell
cmake --build build --config Release --target lab54_emulator
.\build\bin\Release\lab54_emulator.exe
```

## Как проверяется

* Флаг печатает программа; в репо — только его sha256 (`check/expected.json`, `"runs": 3`).
* Автопроверка (CTest): `lab54_build`, `lab54_solve_ok`, `lab54_wrong_fails`. Selftest при каждом старте кладёт
  гостевую RAM в новое место; верный ответ идёт цепочкой через `Machine::ram` (+0x08) и проходит в 3 запусках.
  Неверные ответы: гостевой адрес как смещение внутри объекта эмулятора, счёт на байт левее, счёт в big-endian,
  `ramSize` вместо указателя, лишняя жизнь.
* `solve/solve.py` — спойлер.

## Где пригодится на карте

Игры в эмуляторах (Cemu, Ryujinx, PCSX2, Dolphin): значения ищутся в гостевой памяти, а таблица строится от базы
гостевой RAM, которую держит эмулятор.
