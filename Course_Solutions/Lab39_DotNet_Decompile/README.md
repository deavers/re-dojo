# Lab 39 — .NET: Decompile Your Own C# Game (Tier B- · 4.7)

**Предпосылки:** Lab 07 (классы, таблицы методов).
**Новая идея:** управляемый код сохраняет почти всё, что теряет нативный бинарник: имена типов и методов,
читаемый поток управления. Открой `Lab39.dll` в декомпиляторе .NET (dnSpyEx / ILSpy), найди, как торговец
«выковывает» парольную фразу, повтори вычисление и скажи её. Второй путь (необязательный, не проверяется
автоматически): поправить IL-проверку в dnSpyEx и сохранить модуль.

## Цель

Сказать торговцу парольную фразу. Игра печатает флаг. Фразы в исходнике нет — она вычисляется из массива `Gears`.

| Код выхода | Значение |
| :-: | :--- |
| 0 | принято, флаг напечатан |
| 1 | неверная фраза |
| 2 | пустая строка или длиннее 64 символов |
| 3 | конец ввода |

## Сборка и запуск (нужен .NET SDK 8)

```powershell
dotnet build Course_Solutions/Lab39_DotNet_Decompile/game/Lab39.csproj -c Release -o build/dotnet/lab39/out
.\build\dotnet\lab39\out\Lab39.exe
```

Через CTest проект сначала копируется в папку сборки (`build/dotnet/lab39/src`), чтобы `obj/` и `bin/` не
появлялись в репо.

## Как проверяется (`"ci": "sources_only"`)

* **Локально, с .NET SDK** (`DOJO_DOTNET_TESTS=ON`, по умолчанию): `lab39_build` (`dotnet build`, предупреждения
  C# — ошибки), `lab39_solve_ok`, `lab39_wrong_fails` + `lab39_sources`.
* **В CI** (`-DDOJO_DOTNET_TESTS=OFF`): только `lab39_sources` — проверка исходников без SDK: `net8.0`, без NuGet
  (сборка офлайн), в `Program.cs` есть генератор фразы, флаг и все коды выхода, `solve.py` выводит фразу из
  исходников и содержит неверные ответы, `expected.json` — sha256.
* Неверные ответы: забыт `- i`, нижний регистр, задом наперёд, половина фразы, пустая строка (код 2).
* `solve/solve.py` — спойлер: разбирает `Gears` из `Program.cs` и повторяет вычисление.

## Где пригодится на карте

Игры на .NET / XNA / MonoGame и Unity Mono: логика читается почти как исходник (Terraria, Stardew Valley,
игры на Unity Mono).
