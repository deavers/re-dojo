# Lab 32 — Shadow VMT (Tier C · 3.9)

**Предпосылки:** Lab 07 (vptr, таблица виртуальных методов, ReClass.NET).
**Новая идея:** все объекты класса разделяют одну таблицу виртуальных методов. Правка этой таблицы меняет
поведение всех объектов сразу, а в настоящем бинарнике она ещё и лежит в памяти только для чтения. Точный
способ — «теневая» таблица: скопировать таблицу в свою память, поменять один слот в копии и направить на копию
vptr только нужного объекта.

## Цель

Подкупить Капитана (третий стражник): `IsBribable()` должен вернуть `true` **только** для него. Если подкупным
станет любой другой стражник, Маршал всё заметит. У Торговца уже есть `IsBribable()`, который возвращает `true`.

## Сборка и запуск

```powershell
cmake --build build --config Release --target lab32_shadow_vmt
.\build\bin\Release\lab32_shadow_vmt.exe
```

## Как проверяется

* Флаг печатает программа; в репо — только его sha256 (`check/expected.json`).
* Раскладка таблицы одинакова в MSVC и GCC: одиночное наследование, нет виртуального деструктора, слоты в порядке
  объявления. Вызовы идут через `volatile`-указатель, поэтому компилятор не может обойти vptr.
* Автопроверка (CTest): `lab32_build`, `lab32_solve_ok`, `lab32_wrong_fails`. Selftest использует команды
  `vcopy` / `vset` общего харнесса; исходные таблицы зарегистрированы только для чтения. Неверные ответы, которые
  обязаны провалиться: правка общей таблицы, теневая таблица не тому стражнику, не тот слот, подкуп всех троих,
  копирование далеко за конец таблицы, «vptr» не по тому смещению.
* `solve/solve.py` — спойлер.

## Где пригодится на карте

Хуки методов конкретного объекта в C++-движках: поменять поведение одной сущности, не трогая остальные того же
класса, и без записи в защищённую от записи таблицу.
