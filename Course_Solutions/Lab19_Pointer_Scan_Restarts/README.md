# Lab 19 — Pointer Scan Across Restarts (Tier E+ · 2.1)

**Предпосылки:** Lab 18 (статический указатель, ленивая инициализация, цепочка из трёх уровней).
**Новая идея:** при каждом запуске куча раскладывается иначе (случайный порядок выделений и мусорные выделения
между ними), поэтому адрес золота героя меняется. Сканер указателей Cheat Engine + перезапуск + повторный скан,
пока не останутся только пути, которые переживают перезапуск. Два указателя выглядят правильными при первом
запуске, но это ловушки: один ведёт к другому существу, другой — к устаревшей копии героя.

## Цель

Купить Корону: герою нужно не меньше 777777 золота. Ответ — путь, который работает после трёх перезапусков.

## Сборка и запуск

```powershell
cmake --build build --config Release --target lab19_pointer_scan
.\build\bin\Release\lab19_pointer_scan.exe
```

## Как проверяется

* Флаг печатает программа; в репо — только его sha256 (`check/expected.json`, `"runs": 3`).
* Автопроверка (CTest): `lab19_build`, `lab19_solve_ok`, `lab19_wrong_fails`. Selftest при каждом старте строит
  мир с новой случайной раскладкой кучи; раннер запускает его **3 раза** для верного ответа и 3 раза для каждого
  неверного. Неверные ответы (обе ловушки, сосед по списку, счётчик вместо указателя, не то поле) обязаны
  проваливаться на каждом запуске — это гарантировано устройством лабы, а не случаем.
* **Что проверяется вручную:** автопроверка проверяет путь от статического объекта `g_World`. Сам адрес
  `g_World` в виде module+offset зависит от компилятора и сборки — его ты проверяешь в Cheat Engine на трёх
  перезапусках своей сборки.
* `solve/solve.py` — спойлер.

## Где пригодится на карте

Любая игра, где значения лежат в куче: стабильная таблица Cheat Engine держится на пути от модуля игры,
проверенном перезапусками.
