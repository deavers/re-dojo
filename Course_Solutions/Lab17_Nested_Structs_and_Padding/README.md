# Lab 17 — Nested Structs & Padding (Tier E · 1.6)

**Предпосылки:** Lab 16 (массив структур, шаг).
**Новая идея:** в настоящих объектах структуры вложены друг в друга, а компилятор вставляет выравнивание,
чтобы каждое поле стояло на границе своего размера. Упакованная структура (`#pragma pack(1)`) выравнивания
не имеет вовсе. Разметь героя в Structure Dissect / ReClass.NET и найди реальные смещения полей.

## Цель

Герой становится легендой, когда одновременно:

| Требование | Где лежит | Ограничение в игре |
| :--- | :--- | :--- |
| Крит ≥ 1.0 | `double` во вложенной Stats | тренировка останавливается на 0.50 |
| Прочность брони = 9999 | `uint16` во вложенной Armor | ремонт останавливается на 2000 |
| Цена добычи = 1000000 | `uint32` в **упакованной** структуре | оценщик её не меняет |

## Сборка и запуск

```powershell
cmake --build build --config Release --target lab17_nested_padding
.\build\bin\Release\lab17_nested_padding.exe
```

## Как проверяется

* Флаг печатает программа; в репо — только его sha256 (`check/expected.json`).
* Смещения закреплены `static_assert` и одинаковы для MSVC и GCC (x64).
* Автопроверка (CTest): `lab17_build`, `lab17_solve_ok`, `lab17_wrong_fails`. Неверные ответы, которые обязаны
  провалиться: выравнивание проигнорировано (крит сразу после ловкости), упакованная добыча считается
  выровненной, паддинг брони пропущен, крит записан как float, запись за конец героя.
* `solve/solve.py` — спойлер.

## Где пригодится на карте

Объекты игроков и предметов в C++-движках: вложенные компоненты, выравнивание перед `double` и указателями,
упакованные структуры в сохранениях и сетевых пакетах.
