# RE:DOJO — учебный план лаб и крякми

Утверждённый план (ветка `dojo-labs`). Машиночитаемая версия: [`data/labs_index.json`](../data/labs_index.json),
шаблон лабы: [`Tools_and_Scripts/lab_template/`](../Tools_and_Scripts/lab_template/README.md).

**Правила.** Только собственные бинарники. Никакого обхода защит коммерческого ПО. Малварь — только в изолированной
VM и без сэмплов в репо (в этом плане её нет). Новый C/C++ — в стиле Allman (скобки на отдельных строках),
старые файлы не переформатируются. Тиры и XP существующих 18 позиций не меняются; новые позиции получают тир
по порогам сложности из `rpg_manager.TIERS`.

## Решения автора

| № | Решение |
| :-: | :--- |

| 3 | Имена exe в `Dojo_Labs_Reference.CT` (lab04, lab06): исправлять через имена в сборке, `.CT` не меняется; дифф ждёт ревью |

| 8 | Без пуша до слова автора |

## 3. Шаблон лабы и автопроверка

Структура папки, договорённость по кодам выхода и три обязательных теста (`labNN_build`, `labNN_solve_ok`,
`labNN_wrong_fails`) — в [`Tools_and_Scripts/lab_template/README.md`](../Tools_and_Scripts/lab_template/README.md).
Регистрация — `dojo_add_lab(...)` из [`cmake/DojoLab.cmake`](../cmake/DojoLab.cmake), раннер —
[`Tools_and_Scripts/lab_runner.py`](../Tools_and_Scripts/lab_runner.py).

Сборка (основной компилятор автора — MSVC из Visual Studio 2022; в CI — GCC на Ubuntu и MSVC на windows-latest):

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

CI (`.github/workflows/opsec_and_integrity_ci.yml`): push в `main`, `master`, `dojo-*` и PR — Linux-задача
(GCC) запускает `ctest -LE "windows|unity"`; задача `windows-labs` (MSVC, все тесты кроме `unity`) — только на PR
и на `main`.

## 4. Лабы на карте

* Источник правды — `data/labs_index.json`: `status` (built / planned), `prereqs`, `trains`, `check`, `platform`.
  Строка в таблице Dojo в README нужна только собранным лабам; сборщик сверяет её с индексом (тир, сложность).
* Рёбра лаба → лаба берутся из `prereqs` (неявной цепочки LabN → LabN−1 больше нет).
* Рекомендации игре: для каждой её техники — **две самые лёгкие собранные лабы**, у которых техника есть в `trains`.
* Запланированные лабы в `redirect_labs` ограниченных узлов показываются текстом
  (`safety.redirect_labs_planned`): без ребра и без ссылки из подсказки, пока лаба не собрана.
* На плитке лабы — подписи «только Windows» и «нужен Unity».

## 5. Оценка стоимости

≈ 4,2 тыс. токенов вывода на лабу (исходник ~1,5; core/selftest или checker ~1,0; solve + expected ~0,6;
README ~0,5; 3 подсказки ~0,4; CMake/индекс ~0,2). Партия из 10: ~42 тыс., с итерациями 60–90 тыс.;
входных — порядка 0,5–1,5 млн за партию (в основном кэш). Дороже — .NET, Unity, Lua; дешевле — крякми на stdin.
