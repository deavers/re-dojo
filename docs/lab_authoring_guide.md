# Как добавить лабу RE:DOJO — короткое руководство

План и шаблоны категорий: [`docs/lab_plan.md`](./lab_plan.md). Базовый шаблон: [`Tools_and_Scripts/lab_template/`](../Tools_and_Scripts/lab_template/README.md).
Правила проекта: только свои бинарники, никакого обхода защит коммерческого ПО, никаких выдуманных адресов /
смещений / версий, малварь — только в изолированной VM и без сэмплов в репо. Новый C++ — Allman (скобки на отдельных строках).

## 1. Выбери категорию и образец

| Категория | Образец | Проверка |
| :--- | :--- | :--- |
| Память: типы, структуры, указатели | Lab 11–18 | selftest (`poke` / `chain`) |
| Pointer scan через перезапуски | Lab 19 | exe сам: пункт меню «цепочка смещений», проверка на 3 пересобранных мирах |
| VMT | Lab 32 | selftest (`vcopy` / `vset` / `vswap`) |
| Эмулятор | Lab 54 | selftest (`chain` через указатель на гостевую RAM), `runs: 3` |
| Чекер артефакта / мини-UE | Lab 45 | selftest-чекер сравнивает дамп со своей памятью; порядок зависит от seed |
| Встроенная Lua | Lab 52 | selftest `luado`, `LIBS lua54` |
| Крякми (stdin) | CM 09 | бинарь сам, `FLAG{...}` |
| Крякми с вызовом | CM 10 | бинарь печатает `CHALLENGE:`, `solve.py` — `answer_for` / `expected_flag`, `runs: 3` |
| Крякми с VM | CM 17 | бинарь сам, байткод из ассемблера вне репо |
| .NET / C# | Lab 39 | `dojo_add_dotnet_lab`; `<id>_sources` всегда, dotnet-тесты локально (`ci: sources_only`) |
| Z3 / символьное | CM 16 | бинарь сам, 64-битные неизвестные, `solve.py` решает в z3, `LABELS z3` |

## 2. Чеклист

1. Папка по образцу + копия `Tools_and_Scripts/lab_template/.clang-format`.
2. Флаг вычисляет бинарь (FNV-1a от «печати»); в `check/expected.json` — только sha256. Хэш считает **независимая**
   реализация (Python), а не вывод самого бинаря.
3. **Нейтральная печать + ответ.** Печать — `"<id>|<значения ответа>"` (или значение, зависящее от запуска:
   challenge, seed), прочитанные из состояния после решения. В печати нет слов о технике решения. Цель — **точная**
   (`==`, а не `>=`), чтобы ответ был единственным и флаг не получался «чем-нибудь побольше».
4. **Победа требует именно изучаемую технику.** Условие победы проверяет признаки техники, а не только видимый
   результат (Lab 32: своя копия таблицы + ровно один изменённый слот у этого объекта; Lab 19: путь проверяется на
   3 пересобранных мирах; Lab 11: ширина записи и побочные поля).
5. `solve/solve.py`: `answer()` и `WRONG` — каждый неверный ответ обязан давать код 1 или 2 (падение / таймаут = FAIL).
   **В `WRONG` есть обходные случаи:** значение выше цели, другой способ получить тот же видимый эффект (чужой vptr
   целиком, запись не той ширины, табличный дамп вместо порядка вставки, ответ для другого challenge / seed).
6. Коды выхода: 0 решено · 1 неверно · 2 формат / не разрешено · 3 выход / конец ввода.
7. `static_assert` на каждое смещение из эталонного ответа; только типы фиксированной ширины; `char16_t`, не `wchar_t`.
8. `CMakeLists.txt`: `dojo_add_lab(ID … TARGET … DIR … SOURCE … [SELFTEST …] [LIBS …] [LABELS windows])`.
9. `data/labs_index.json`: `status: "built"`, `prereqs` (только **собранные** лабы; план — в `prereqs_plan`),
   `trains`, `check`, `platform`, `ci`. **Тир:** для новых и исправляемых лаб — `rpg_manager.score_to_tier(difficulty_raw)`
   (`Tools_and_Scripts/rpg_manager.py`), это источник правды. Тиры исходных 18 позиций заданы вручную — не трогать.
   Тир в строке README, в шапке исходника и в баннере exe совпадает с индексом.
10. Строка в таблице Dojo в `README.md` (формат как у соседних строк; **README в CRLF — сохранить CRLF**). Ячейка
    «концепт» нейтральная: что за задача, без названия приёма решения.
11. `data/notes_index.json` → `labs.<id>`: `core.hpp` как `lab_source` (иначе литералы из него не подтверждены).
12. 3 подсказки в `data/hints/labs_01.json` (`draft`): `my_notes` только со ссылками на файлы этой лабы.
    **Каждый литерал** (hex, `+0x..`, AOB, версии вроде `0.999`, `16.16`) должен целым токеном встречаться в своих
    источниках или строке README. Названия коммерческих защит — только у restricted-узлов.
13. **README лабы — только цель и формат ввода** (+ коды выхода, сборка, как проверяется). Никакой механики: типы,
    смещения, форматы артефактов, внутриигровые лимиты, маршрут решения — во 2–3 подсказки. Заголовок не называет
    приём. Если в README было что-то уникальное — сначала перенести в подсказку, потом удалить.
14. Интерактивная лаба (CM 10): бинарь печатает `CHALLENGE: <v>` с `std::endl`; `solve.py` — `answer_for(v)` и
    `expected_flag(v)`, `expected.json` — `"flag": "computed ..."` и `"runs": 3`; элементы `WRONG` могут быть функциями.

## 3. Команды

```powershell
# CTest должен видеть Python с z3: один раз при конфигурации (Windows: Python 3.12; WSL: venv с z3)
cmake -S . -B build -A x64 -DPython3_EXECUTABLE="<python с z3-solver>"   # .NET-тесты: нужен SDK, DOJO_DOTNET_TESTS=ON
python -X utf8 Tools_and_Scripts/build_games_json.py; python -X utf8 Tools_and_Scripts/build_dojo_map.py
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure            # полная автопроверка, не только <id>_
wsl -e bash -lc "cmake -S . -B <dir> -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_FLAGS='-Wall -Wextra -Werror' && cmake --build <dir> && ctest --test-dir <dir>"
python -X utf8 Tools_and_Scripts/validate_games.py; python Tools_and_Scripts/tests/test_validator_fixtures.py
node Tools_and_Scripts/tests/e2e_dojo_map.mjs; python -X utf8 Tools_and_Scripts/opsec_sanitizer.py --ci
```
Лаба принята, только если `<id>_build`, `<id>_solve_ok`, `<id>_wrong_fails` зелёные на MSVC **и** GCC, а полный прогон
обоих компиляторов, валидатор, фикстуры, e2e и opsec — зелёные после **каждого** коммита. В отчёт — число
предупреждений MSVC и GCC при чистой пересборке целей лабы (`--clean-first`, grep по выводу), а не только тесты.

## 4. Типичные ошибки из прошлых партий

* **Устаревший `.pyc`:** кэш байткода по mtime-секундам + размеру давал старый `solve.py` → runner отключает кэш.
* **CRLF:** README в индексе с CRLF; запись через Python с LF превратила дифф в «весь файл» → читать и писать байтами.
* **Сужение типов:** `rng()` (unsigned long на Linux) в `{}`-инициализаторе `uint32_t` — `-Wnarrowing` только на GCC
  → явный `static_cast`; смотреть **все** строки сборки, не только тесты.
* **Литералы не из исходников:** `12.50` (значение на экране), `+0x0300` при `0x0300` в коде → валидатор отклоняет.
* **Девиртуализация:** вызовы через `volatile`-указатель, иначе правка vptr не влияет.
* **ADL:** свободная функция в exe с тем же именем, что в `namespace labNN` (`VptrOf`), стала неоднозначной → другое имя.
* **`__declspec` вне Windows:** `LUA_BUILD_AS_DLL` только для `WIN32`.
* **Не тот Python у CTest:** `find_package` взял 3.14 / системный python3 без z3 → `-DPython3_EXECUTABLE`, раннер с `-I`.
* **PDB с локальным путём:** `dotnet build` писал PDB с путём пользователя (opsec сканирует `build/`) → `DebugType=none`.
* **Windows-путь в WSL:** `C:/...` внутри `wsl -e bash` стал относительной папкой `C:` в репо → в WSL только `/mnt/c/...`.
* **Суффиксы литералов:** в коде `0xFFFFU` — в подсказке тоже `0xFFFFU`, иначе валидатор не найдёт токен.
* **Экранирование в heredoc:** `\v` в Python-строке стал управляющим символом в YAML → правки сложных строк через файл/Edit.
* **Коллизия seed:** при `Rng{seed | 1}` чётное N и N+1 дают один порядок → «другой seed» в `WRONG` брать N+2.
* **Медленный z3:** `Not(...)` от 64-битного умножения решался 273 с → ключи ослабленных систем искать без отрицания
  и проверять выброшенное ограничение в Python.
* **Синтетический merge-коммит PR:** checkout по умолчанию берёт merge-коммит GitHub (автор — отображаемое имя
  профиля) → opsec ложно падал; CI берёт `ref` = head sha PR. Проверку утечек не ослаблять.

## 5. Независимое ревью партии перед пушем

Перед пушем партии — ревью **отдельной** моделью / сессией без контекста авторства (ей виден только дифф и правила).
Находки — таблицей; каждая исправляется отдельным коммитом с полным прогоном раздела 3; пуш — только по слову автора.

```text
Ты — независимый ревьюер партии лаб RE:DOJO (ветка dojo-labs, коммиты <from>..<to>). Ничего не правь и не пушь.
Прочитай docs/lab_authoring_guide.md и docs/lab_plan.md, затем каждую лабу партии: исходник, core.hpp, selftest,
solve/solve.py, check/expected.json, README лабы, её строку Dojo в README.md, подсказки в data/hints/labs_01.json.
Для каждой лабы ответь:
1. Решаема ли она только изучаемой техникой? Найди обход (другая запись, чужой vptr, табличный дамп, значение
   больше цели, заранее записанный ответ) — проходит ли он? Есть ли он в WRONG?
2. Печать флага нейтральна и содержит ответ / значение запуска? Цель точная? Флаг нельзя получить, не решив?
3. README — только цель и формат ввода? Не выдаёт ли механику README, заголовок или ячейка «концепт»?
4. Подсказки: 1 — направление, 2–3 — механика; литералы есть в исходниках; нет выдуманных адресов / версий.
5. Тир = score_to_tier(difficulty_raw) для новых лаб, совпадает в индексе, README, шапке и баннере; prereqs — собранные.
6. Крякми: реален ли перебор (оценка времени), уникален ли ответ, не похож ли формат на реальные данные (карты).
7. Правила проекта: только свои бинарники, без обхода коммерческих защит, без сэмплов малвари, Allman в новом C++.
Выведи таблицу: лаба | находка | серьёзность (high / medium / low) | предложенное исправление. Без воды.
```

## 6. Решения и исключения

Решения автора по итогам ревью партии (не «исправлять» при следующих ревью):

* **Тиры:** для новых и исправляемых лаб тир = `rpg_manager.score_to_tier(difficulty_raw)` — источник правды;
  индекс, строка README, шапка исходника и баннер exe совпадают. Тиры исходных 18 позиций заданы вручную и не меняются.
* **Lab 54:** README оставляет гостевые адреса `0x0300` / `0x0302`, их ширину и little-endian — это «мануал консоли»,
  часть условия, а не механика решения.
* **Lab 07:** в шапке исходника «Tier C», в индексе C- — исходная позиция с ручным тиром, не трогать.
* **Lab 45:** exe по-прежнему печатает флаг за три имени (ручной игровой путь); флаг зависит от seed запуска,
  полный дамп проверяет отдельный чекер.

## 7. Промпт-шаблон для более простой модели

```text
Сделай лабу <id> из docs/lab_plan.md по шаблону категории «<категория>» (образец: <образец>, раздел
«Шаблоны категорий» в docs/lab_plan.md) и по docs/lab_authoring_guide.md. Ветка dojo-labs.
Правила: только свои бинарники; без выдуманных адресов/смещений/версий; Allman для нового C++;
флаг вычисляет бинарь, печать нейтральная + ответ, цель точная; в expected.json только sha256 из независимой
реализации; победа требует изучаемую технику; WRONG — минимум 5 случаев с кодом 1 или 2, включая обходные;
README лабы — только цель и формат ввода, механика — в подсказках 2–3; тир = score_to_tier(difficulty_raw).
Пройди весь чеклист раздела 2. Прогони команды раздела 3 (MSVC и GCC -Werror, валидатор,
регрессионный тест, e2e, opsec). Закоммить лабу отдельным коммитом, не пушь.
Покажи таблицу: лаба | build/solve_ok/wrong_fails (MSVC, GCC) | предупреждения MSVC | предупреждения GCC |
≈ токены | итерации исправлений с причинами. Если чего-то нет в окружении — ничего не ставь, остановись и скажи.
```
