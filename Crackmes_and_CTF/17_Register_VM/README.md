# CM 17 — The Register Machine (Tier S- · 7.4)

**Предпосылки:** CM 06 (стековая VM, свой дизассемблер).
**Новая идея:** регистровая виртуальная машина — четыре 32-битных регистра, флаг сравнения и абсолютный
переход. Проверка ключа написана не на C++, а байткодом. Найди цикл диспетчера, восстанови смысл каждого
опкода, напиши дизассемблер программы и обрати проверки. Каждая проверка зависит от результата предыдущей через
регистр-накопитель.

## Цель

Ввести 8-символьный ключ, который байткод принимает (`HALT_OK`). Программа печатает `FLAG{<ключ>}`.

| Код выхода | Значение |
| :-: | :--- |
| 0 | принят, флаг напечатан |
| 1 | отклонён байткодом (`HALT_FAIL`) |
| 2 | неверная длина или сломанная программа |
| 3 | конец ввода |

## Сборка и запуск

```powershell
cmake --build build --config Release --target crackme17_register_vm
.\build\bin\Release\crackme17_register_vm.exe
```

## Как проверяется

* В репо — только sha256 флага (`check/expected.json`); ключа в исходнике нет, только байткод.
* `solve/solve.py` — эталон (спойлер): извлекает `kProgram` из исходника, дизассемблирует и **символьно**
  обращает цепочку операций над байтом ввода, ничего не зная о ключе заранее.
* Автопроверка (CTest): `cm17_build`, `cm17_solve_ok`, `cm17_wrong_fails`. Неверные ответы, которые обязаны
  провалиться: последний символ сдвинут, первый символ сдвинут (через накопитель ломает все дальнейшие проверки),
  ключ задом наперёд, нижний регистр, 7 символов (код 2).
* VM проверяет границы операндов и `pc`: испорченная программа даёт код 2, а не падение.
