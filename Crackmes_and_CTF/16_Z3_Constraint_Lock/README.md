# CM 16 — The Constraint Lock (Tier A · 6.6)

**Предпосылки:** CM 10 (серийник по правилам); CM 13 (строки из XOR-фрагментов) — в плане, ещё не собрана.
**Новая идея:** ключ — четыре 32-битных числа, связанных пятью ограничениями: сложение с переполнением, XOR,
циклический сдвиг, умножение по модулю 2^32 и смешивание по маске. Вручную долго — опиши ограничения
SMT-решателю (Z3, битовые векторы ширины 32) и найди ключ. Решение единственное (проверено z3 при создании).

## Цель

Ввести ключ `XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX`. Программа печатает `FLAG{<ключ>}`.

| Код выхода | Значение |
| :-: | :--- |
| 0 | принят, флаг напечатан |
| 1 | нарушено ограничение |
| 2 | неверный формат |
| 3 | конец ввода |

## Сборка и запуск

```powershell
cmake --build build --config Release --target crackme16_z3_lock
.\build\bin\Release\crackme16_z3_lock.exe
```

## Как проверяется

* В репо — только sha256 флага (`check/expected.json`); ключа нет ни в исходнике, ни в `solve.py`.
* `solve/solve.py` (спойлер) читает константы из исходника и решает систему в Z3. Нужен `z3-solver`
  (тесты помечены `z3`; CTest должен запускать Python, в котором он установлен: `-DPython3_EXECUTABLE=…`).
  В CI ставится `pip install z3-solver==5.4.1.0` в обеих задачах.
* Автопроверка (CTest): `cm16_build`, `cm16_solve_ok`, `cm16_wrong_fails`. Неверные ответы: последняя компонента
  +1, `a` и `b` переставлены, ключ системы без ограничения умножения, ключ системы без ограничения по маске
  (оба найдены z3 с условием «нарушает выброшенное ограничение»), неверный формат (код 2).
